# Оптимизация загрузки каталога и обложек

Четыре изменения, каждое привязано к конкретной строке кода, которую можно проверить.

---

## 1. Обложка больше не скачивается восемь раз

**Было.** `CoverArtImage` собирал ключ так:

```kotlin
val stableKey = "${idParam}-${sizePx}"     // диск и память
```

А `sizePx` в интерфейсе восемь разных: 112 (превью), 128, 176, 200 (мини-плеер и уведомление),
256 (малая карточка), 300 (по умолчанию), 304 (сетка альбомов), 500 (полноэкранный плеер).
Размер уходил в URL, сервер отдавал картинку ровно этого размера, и ключ кэша его включал.

Итог: **одна обложка — до восьми сетевых запросов и восьми копий на диске.** На экране с
сеткой альбомов это основной объём трафика и основной источник лагов при скролле.

**Стало.** Размер квантуется до двух «корзин» (`util/Constants.kt`):

```kotlin
object CoverArt {
    const val LIST  = 300   // списки, сетки, превью
    const val LARGE = 600   // полноэкранный плеер
    private const val LARGE_THRESHOLD = 400
    fun bucket(requestedPx: Int): Int = if (requestedPx > LARGE_THRESHOLD) LARGE else LIST
}
```

* `MusicRepository.getCoverArtUrl()` просит у сервера только `CoverArt.bucket(size)`.
* Ключ **диска** — `id + размер из URL`, то есть один на корзину.
* Ключ **памяти** — `id + размер + sizePx`, потому что Coil декодирует под конкретный
  отображаемый размер, и 56dp-превью не должно вытеснять из памяти 152dp-карточку.
* `.size(sizePx)` `Coil` сам уменьшает 300px до нужного.

Порог 400, а не 300, намеренно: при пороге 300 самый частый размер 304 (сетка альбомов)
уходил бы в корзину 600 — и карточка в списке тянула бы картинку вдвое больше нужной.

**Итог: 8 запросов → 2.**

Попутно убран `allowHardware(false)` из `ImageRequest`: при заданном `bitmapConfig` Coil и так
отключает аппаратные битмапы, то есть прежний явный запрет ни на что не влиял, но вводил в
заблуждение при чтении кода.

## 2. Появился дисковый кэш ответов API

**Было.** В `NetworkModule` не было `okhttp3.Cache` вообще, а Navidrome не отдаёт заголовков
кэширования. Каждый вход в «Библиотеку» заново тянул альбомы, артистов, плейлисты и избранное —
даже если пользователь только что оттуда вышел.

**Стало.** Дисковый кэш 50 МБ + сетевой перехватчик, который дописывает `Cache-Control`:

* `getCoverArt.view` — 30 суток (обложка для данного id неизменна);
* остальной каталог — 5 минут;
* аудио (`stream.view`, `download.view`) и любые изменения (`scrobble`, `star`,
  `savePlayQueue`) в белый список не входят и не кэшируются никогда.

Перехватчик добавлен как `addNetworkInterceptor`, а не `addInterceptor`: он должен дописать
заголовок **до** того, как ответ попадёт в кэш OkHttp. Обычный перехватчик выполнился бы уже
после кэша и ничего бы не изменил.

Чтобы pull-to-refresh не возвращал закэшированное, в API-интерфейс добавлен
`@Header("Cache-Control") cacheControl: String? = null`, а в репозиторий — параметр
`forceRefresh`. Явное обновление передаёт `no-cache`, OkHttp идёт в сеть.

## 3. Экран больше не ждёт самый медленный запрос

**Было.** Четыре запроса запускались параллельно, но состояние обновлялось один раз — после
`await()` всех четырёх:

```kotlin
val artistsDef   = async { repository.getArtists() }
val albumsDef    = async { repository.getAlbums("alphabeticalByName", 100) }
val playlistsDef = async { repository.getPlaylists() }
val starredDef   = async { repository.getStarred() }
// ... await() всех четырёх, и только потом одно обновление состояния
```

Если альбомы пришли за 300 мс, а избранное тянется 3 с, все вкладки пустуют 3 секунды.

**Стало.** Каждая часть обновляет состояние сама, по мере готовности. Счётчик оставшихся
сбрасывает `isLoading` / `isRefreshing`, когда доехали все.

---

## 4. Настоящая постраничная загрузка альбомов

**Было.** `getAlbums("alphabeticalByName", 100)` тянул **сотню альбомов сразу**, из них
показывал 20. Кнопка «Загрузить ещё» просто увеличивала счётчик — сеть не трогала, потому что
все 100 уже были скачаны. Платили за 100 (трафик, разбор JSON, обложки), видели 20.

**Стало.** Первая страница (50) при открытии, дальше — по кнопке с реальным `offset`. Признак
конца: сервер вернул меньше, чем просили. На всякий случай страницы склеиваются через
`distinctBy { it.id }` — выдача могла сдвинуться между запросами.

Артисты и избранное остались с обрезкой на клиенте: `getArtists` и `getStarred` серверной
пагинации не имеют, отдают всё сразу.

## Проверка

`kotlinc 2.0.21`: 0 синтаксических ошибок, скобки сбалансированы во всех восьми файлах.
Остальные диагностики — отсутствующие в песочнице okhttp3/Hilt/Retrofit; это ожидаемо, в проекте
они есть. Сборка на устройстве покажет окончательно.
